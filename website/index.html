Attendance ERP

In-progress prototype. The code is private.

A college attendance system where recognising a face is only the first step.

Attendance also needs enrolment, records that people can check, and reports. I’m building those parts too.

  1. Capture

    Camera frames come in for recognition.

  2. Match

    InsightFace suggests likely matches among enrolled students.

  3. Record

    Each match becomes an attendance record.

  4. Review

    A person checks uncertain matches. Records feed the reports.

What I’m building

  • A Flask and PostgreSQL app that connects InsightFace recognition to enrolment, attendance records, review and reports.
  • Background processing with Celery and Redis, plus bulk imports.
  • Testing capture quality, replay scenarios and the CPU fallback for machines without a GPU.

Where it stands

The ERP code is private. The public repository is an earlier, simpler attendance prototype, not the current implementation.

Earlier prototype on GitHub, Attendance ERP (opens in a new tab)

Camera conditions affect recognition, so uncertain matches need review. Student photos and attendance records stay private.

Built with

Python, Flask, PostgreSQL, InsightFace, Celery and Redis.

Satellite research

Research prototype. The code is private.

Screening satellite images for possible oil spills, so a person knows where to look more closely.

  • Compared U-Net and DeepLabV3 in PyTorch, choosing on validation results and testing on a separate held-out set.
  • Exported a model for CPU inference with ONNX Runtime, and added checkpoints so training can resume.

A flagged region is a lead to investigate, not a confirmed oil spill. Imagery alone cannot establish which vessel was responsible.

Built with PyTorch and ONNX Runtime.

Vendor Payment Memory Agent

Hackathon demo. The code is public.

A hackathon demo that remembers how earlier invoice exceptions were resolved, and suggests a next step for a person to approve.

  • Recalls earlier resolutions through Hindsight, with a local JSONL fallback when the memory service is unavailable.
  • Checks GSTIN, HSN and purchase-order fields, and catches duplicate invoices, before it suggests anything.

It runs on example invoices and vendors, not client records. A person makes every decision. The demo does not authorise or execute payments.

Built with Python, FastAPI, Hindsight and JSONL. Code on GitHub, Vendor Payment Memory Agent (opens in a new tab)
